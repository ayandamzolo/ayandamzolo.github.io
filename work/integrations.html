The problem with a submission that goes nowhere

A home loan application is not a message. It is a person's house, a deposit already paid, and a deadline in a sale agreement. When a submission fails loudly, somebody fixes it. When it fails quietly, the application simply sits, and the first person to notice is the customer asking why nothing has happened.

So the work is less about moving data than about making sure no state can be reached where something is lost and nobody has been told.

Changing vendor without asking anyone to resubmit

The platform changed the vendor it submits through. The obvious approach is a configuration flag and a migration: flip everyone to the new vendor on deploy day. That breaks every application already in flight, because the old vendor holds its state and the new one has never heard of it.

Instead, each bank submission is stamped with the time it was sent, and the vendor is resolved by comparing that stamp against the cutover date. Submission time decides the route, not deploy time.

Two months later, onboarding the next lender was a configuration addition rather than a code change, because the resolver already knew how to answer the question "which vendor owns this submission" for any date.

Routing, and never rejecting on a technicality

A companion service decides whether an application qualifies for a bank's newer origination system or has to fall back to the legacy one. The important design decision is what happens when a rule fails. The service does not reject the application. It routes it to the fallback and returns every reason it did so, not just the first one it hit.

That difference matters to whoever reads the result. One reason sends someone back around the loop to discover the next one. All of them at once lets the problem be fixed in a single pass.

What the tests actually cover

  • A joint application submitting successfully and landing in the right target system
  • Authentication with a database issued key, including that its last used timestamp is stamped
  • An expired key being refused
  • Amendments and service requests against an application already in flight

Evidence. Primary author of 828 of the lending platform's 968 commits across all branches. The routing service is solo work, running lint and a Pest suite in CI on every push. Vendor cutover and certificate rotation runbooks are committed alongside the code.
